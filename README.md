## 技术速览

- **形态**：单文件静态看板（HTML + JavaScript + ECharts），数据以离线快照形式随页面加载，纯前端渲染、无后端依赖。
- **原理**：业务库（阿里云 AnalyticDB）→ Python 抽取/构建管线 → 脱敏聚合快照 → 静态页面；页面打开即渲染，支持按维度筛选与下钻。
- **用途**：嘟嘟换电统一看板：多来源运营指标汇总一屏。
- **脱敏**：公开发布版本已移除数据库连接信息、账号口令与个人敏感字段，仅保留聚合指标。


> 把「用户协议 / 网点 / 换电柜 / 电池」四类明细收进**同一个链接**，顶部菜单切换，支持关键词搜索、多条件筛选与结果导出。后端从 AnalyticDB 业务库**只读**抽取数据到本地 SQLite 快照库，前端由 Flask 模板渲染。

`Python 3.11` · `Flask` · `SQLite` · `原生 JS` · `GitHub Pages 静态快照`

## 1. 它解决什么问题

日常查数最费时间的不是"看不到总数"，而是"要看某一类明细"：某个网点下的换电柜有哪些、某块电池挂在哪个网点、某个用户签了哪些协议。

- 以前：四类明细分散在四个页面 / 四张导出表，口径与筛选条件各写一遍；
- 现在：一个链接、一套筛选器、一份导出口径，四个菜单共用一个本地快照库。

## 2. 技术原理

### 2.1 同链接多菜单

菜单通过 URL 参数切换，便于直接分享某一块视图：

```
http://127.0.0.1:8090/            # 默认：用户协议
http://127.0.0.1:8090/?m=site     # 网点
http://127.0.0.1:8090/?m=cabinet  # 换电柜
http://127.0.0.1:8090/?m=battery  # 电池
```

### 2.2 数据同步与查询

- `sync.py`：从业务库**只读**抽取协议 / 网点 / 换电柜 / 电池数据，落到本地 SQLite（四张表与页面菜单一一对应），结束时会自动触发建索引；
- `build_index.py`：为高频筛选列（城市、网点、状态、代理商、SN 等）建立索引，保证大表在多条件筛选下仍然流畅；
- `schema_def.py`：集中定义四类数据的字段、表头与分组，前端表头与后端字段一一映射，避免各页面各写一套。

### 2.3 导出

按当前筛选条件生成导出文件（CSV / XLSX）；XLSX 结果按 `XLSX_CACHE_TTL = 3600` 缓存复用，避免同一条件被反复重复生成。

### 2.4 静态快照

`docs/` 为 GitHub Pages 版本：页面结构一致，数据改为读取 `docs/data/*.json`，**纯只读**，不含同步与导出到服务端的能力。

## 3. 目录结构

```
citybike_unified/
├── app.py            # Flask 入口（默认端口 8090）
├── sync.py           # 业务库 → 本地 SQLite 只读同步
├── build_index.py    # 快照库索引与行数缓存
├── schema_def.py     # 四类数据的字段 / 表头 / 分组定义
├── common.py         # 日志与 SQLite 连接
├── config.py         # 端口、快照库路径等本地配置
├── templates/        # 本地运行页面模板
└── docs/             # GitHub Pages 静态快照（index.html + data/*.json）
```

## 4. 本地运行

```bash
pip install -r requirements.txt
python sync.py        # 首次：同步数据并建索引
python app.py         # 打开 http://127.0.0.1:8090/
```
